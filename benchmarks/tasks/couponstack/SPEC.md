# CouponStack — stacking rules, usage limits and redemption rollback

Implement `src/coupons.js` as an in-memory coupon engine. Export `createCoupons({ coupons = [], now = () => 0 } = {})`. `now` is a function returning the current time as a nonnegative safe integer; the engine never reads a wall clock. Money is an integer number of cents. Methods are synchronous, and callers may also `await` them. Inputs and results are plain JSON values.

A coupon definition is `{ code, kind, value, stackable = false, minSubtotal = 0, maxUses = null, perCustomer = null, validFrom = 0, validTo = null, cap = null }`. `createCoupons` throws `INVALID_INPUT` when `coupons` is not an array or a definition breaks one of these rules: `code` is a nonempty string and unique; `kind` is `percent` (then `value` is an integer from 1 to 100) or `fixed` (then `value` is a positive safe integer); `stackable` is a boolean; `minSubtotal` is a nonnegative safe integer; `maxUses`, `perCustomer` and `cap` are `null` or positive safe integers; `validFrom` is a nonnegative safe integer; `validTo` is `null` or a safe integer greater than `validFrom`.

The engine exposes `quote({ customer, lines, codes = [] })`, `redeem({ orderId, customer, lines, codes = [] })`, `cancel(orderId)`, `uses(code)` and `usesBy(code, customer)`.

1. Errors are `Error` objects with a string `code`. A request needs a nonempty string `customer` and a nonempty array `lines` of `{ sku, unitPrice, qty }` with `sku` a nonempty string, `unitPrice` a nonnegative safe integer and `qty` a positive safe integer; `codes` must be an array of strings; `orderId` must be a nonempty string (`INVALID_INPUT`). A code listed twice fails with `DUPLICATE_CODE`; a code that is not a defined coupon with `UNKNOWN_COUPON`. A failed call changes nothing.
2. The `subtotal` is the sum of `unitPrice * qty` over the lines. A coupon is *eligible* when all of these hold, and otherwise the call fails with the first code that applies in this order: it is active, meaning `validFrom <= now()` and (`validTo` is `null` or `now() < validTo`) (`COUPON_NOT_ACTIVE`); the `subtotal` is at least `minSubtotal` (`MIN_SUBTOTAL`); `uses(code) < maxUses` when `maxUses` is set (`COUPON_EXHAUSTED`); `usesBy(code, customer) < perCustomer` when `perCustomer` is set (`LIMIT_REACHED`). The subtotal used here is always the one before any discount. When several listed coupons are not eligible, the first one in the order of `codes` decides the error.
3. A coupon with `stackable: false` cannot be combined with any other coupon: a request that lists it together with another code fails with `NOT_STACKABLE`. Any number of stackable coupons may be combined.
4. Discounts are applied to a running amount that starts at the `subtotal`. First all `percent` coupons, in the order of `codes`: each takes `floor(running * value / 100)`. Then all `fixed` coupons, in the order of `codes`: each takes `value`. For every coupon the amount taken is limited by its `cap` when it has one, and never exceeds what is left of the running amount, so the total never goes below 0. The running amount falls by the amount taken.
5. `quote` returns `{ subtotal, discounts, total }` where `discounts` lists `{ code, amount }` for every listed coupon in the order they were applied (percent coupons first, then fixed ones; a coupon that took nothing is listed with amount 0) and `total` is what is left of the running amount. `quote` changes nothing.
6. `redeem` prices the order exactly like `quote` and returns `{ orderId, subtotal, discounts, total }`; it counts one use of each listed coupon, for the customer of the order. If any coupon is not eligible, nothing is counted and the `orderId` is not remembered.
7. `redeem` is idempotent per `orderId`. A second call with the same `orderId` and an equal request (same `customer`, same `lines` and same `codes` in the same order) counts nothing and returns a deep copy of the result of the first call, even if a coupon has been exhausted or has expired since. The same `orderId` with a different request fails with `ORDER_CONFLICT`.
8. `cancel(orderId)` cancels a redeemed order: every use it counted is given back at once, and it returns `{ orderId, status: 'cancelled' }`. Cancelling an order again returns the same value and gives nothing back a second time. An `orderId` that was never redeemed fails with `UNKNOWN_ORDER`. Redeeming a cancelled `orderId` again fails with `ORDER_CANCELLED`.
9. `uses(code)` is the number of uses currently counted for the coupon over all customers, `usesBy(code, customer)` the number counted for one customer. An unknown code fails with `UNKNOWN_COUPON`.

Error precedence is specified only where stated above; do not test inputs that break several unrelated rules at once. No persistence, network, timers or cleanup is required. Keep the source compact, use the public API in tests, and do not add behavior beyond this contract.
