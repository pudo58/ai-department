# LedgerHold — idempotent deposits, holds, captures and transfers

Implement `src/ledger.js` as an in-memory ledger. Export `createLedger({ now = () => 0, holdTtl = 60 } = {})`. `now` is a function returning the current time as a nonnegative safe integer (seconds); the ledger never reads a wall clock. `holdTtl` is a positive safe integer. Money is a positive safe integer number of cents. Methods are synchronous, and callers may also `await` them. Inputs and results are plain JSON values.

The ledger exposes `open(account)`, `deposit(account, amount, key)`, `hold(account, amount, key)`, `capture(holdId, amount, key)`, `release(holdId, key)`, `transfer(from, to, amount, key)`, `balance(account)` and `getHold(holdId)`.

1. Errors are `Error` objects with a string `code`. `createLedger` throws `INVALID_INPUT` when `holdTtl` is not a positive safe integer. Account names, hold ids and keys are nonempty strings (`INVALID_INPUT`). An amount that is not a positive safe integer fails with `INVALID_AMOUNT`. An account that was not opened fails with `UNKNOWN_ACCOUNT`; a hold id that was never issued fails with `UNKNOWN_HOLD`.
2. `open(account)` creates an account with zero funds and returns its balance view. Opening an account twice fails with `ACCOUNT_EXISTS` and changes nothing.
3. A balance view is `{ total, held, available }`. `total` is the funds in the account, `held` is the sum of the amounts of its active holds, and `available` is `total - held`. A hold is active from the moment it is created while `now() < createdAt + holdTtl`; at `now() >= createdAt + holdTtl` it is expired and no longer counts as held. `balance(account)` returns the view as of `now()`.
4. `deposit` adds `amount` to the account's `total` and returns its balance view.
5. `hold` reserves `amount` of an account's available funds. If `available < amount` it fails with `INSUFFICIENT_FUNDS` (an amount equal to `available` is allowed). It returns `{ holdId, amount, expiresAt }` where `expiresAt = now() + holdTtl`. Hold ids are `"h1"`, `"h2"`, … in creation order, and the counter advances only when a hold is actually created.
6. `capture(holdId, amount, key)` spends from an active hold: `total` falls by `amount` and the hold is closed, so whatever part of the hold was not captured is available again at once. `amount` may not exceed the hold's amount (`OVER_CAPTURE`). A hold that expired fails with `HOLD_EXPIRED`; a hold that was already captured or released fails with `HOLD_CLOSED`. It returns the balance view of the hold's account.
7. `release(holdId, key)` closes an active hold without spending anything and returns the balance view of its account. The same errors as `capture` apply for an expired or already closed hold.
8. `transfer(from, to, amount, key)` moves `amount` out of the available funds of `from` into `to` and returns `{ from, to }` with the two balance views. Held funds cannot be transferred: it fails with `INSUFFICIENT_FUNDS` when `available(from) < amount`. `from` and `to` must differ (`SAME_ACCOUNT`) and both must exist (`UNKNOWN_ACCOUNT`). A transfer that fails changes nothing, not even for the account that exists.
9. `getHold(holdId)` returns `{ holdId, account, amount, status }` where `status` is `active`, `expired`, `captured` or `released`, as of `now()`. A hold that was captured or released keeps that status; only a hold that is still open can become `expired`.
10. Every method that takes a `key` is idempotent. The first successful call with a key applies its effect and its result is remembered. A later call with the same key, the same method and the same arguments applies nothing and returns a deep copy of the remembered result, even if time has passed or other operations have changed the balances since. A later call that uses the key with a different method or different arguments fails with `KEY_REUSED` and changes nothing. A call that fails does not use up its key: the key stays free, and the same key can be used again later for any call. Keys are shared by all methods of one ledger.

Error precedence is specified only where stated above; do not test inputs that break several unrelated rules at once. No persistence, network, timers or cleanup is required. Keep the source compact, use the public API in tests, and do not add behavior beyond this contract.
